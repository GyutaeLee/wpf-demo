# Windows에서 직접 확인하기

자동 시연은 정해진 화면 요소와 서버 값을 확인합니다. 아래 절차는 실제 화면의 가독성, 키보드 사용과 낭독을 확인하기 위한 것입니다. 현재 배율 100%·150%, Narrator와 고대비는 **미검증**입니다. 이 문서를 추가한 것으로 확인을 마친 것은 아닙니다.

## 실행 준비

1. [최신 Windows x64 Release](https://github.com/GyutaeLee/wpf-demo/releases/latest)를 열어 설명을 확인하고, 첨부된 `wpf-demo-windows-demo.zip`을 내려받아 압축을 풉니다.
2. Release 태그, Windows 버전, 화면 해상도와 배율을 아래 양식에 적습니다. 수정한 소스를 빌드했다면 커밋 ID나 변경 파일도 적습니다.
3. ZIP을 푼 폴더에서 PowerShell 창 두 개를 엽니다. 두 창 모두 같은 폴더에 있어야 합니다.

첫 번째 창에서 API를 실행합니다.

```powershell
$env:WPFDEMO_SERVER_DATA_DIR = Join-Path $PWD 'manual-check\server'
.\api\WpfDemo.Api.exe
```

두 번째 창에서 앱을 실행합니다.

```powershell
$env:WPFDEMO_CLIENT_DATA_DIR = Join-Path $PWD 'manual-check\client'
.\client\WpfDemo.exe
```

같은 폴더로 다시 실행하면 이전 대여·반납 결과와 보관 요청을 이어서 사용합니다. 예시 데이터를 새로 준비하려면 두 프로세스를 종료하고 두 명령의 `manual-check`를 `manual-check-2` 같은 새 이름으로 바꿉니다. 평소 사용하던 데이터 폴더를 지울 필요는 없습니다.

API에는 필요한 런타임이 포함되어 있습니다. WPF 앱에는 .NET Framework 4.8 이상이 필요하며 Visual Studio는 필요하지 않습니다. 수동 확인에는 자동 시연용 PowerShell 7이나 WinAppCLI가 필요하지 않습니다.

## 화면과 배율

Windows 설정의 **시스템 → 디스플레이 → 배율**에서 배율을 바꾼 뒤 앱을 종료하고 다시 엽니다. 설정에서 로그아웃을 요구하면 안내를 따릅니다. 다른 해상도를 지원하지 않는 기기에서는 해당 조합을 미검증으로 둡니다.

| 환경 | 확인할 내용 | 결과 |
| --- | --- | --- |
| 1920×1080 · 100% | 첫 화면, 최소 크기, 최대화에서 목록·입력·대여/반납 버튼이 읽히고 접근 가능한지 | 미검증 |
| 1920×1080 · 150% | 글자·상태 배지·메모·이력이 겹치거나 잘리지 않는지 | 미검증 |
| 1366×768 · 150% | 시작 창이 작업 영역에 들어오는지, 상세를 스크롤해 입력·이력에 접근할 수 있는지 | 미검증 |

각 환경에서 장비 검색 → 선택 → 메모 입력 → 대여 → 반납을 한 번 실행합니다. 안내 문구와 이력의 이전·다음 버튼도 확인합니다. 버튼이 보이더라도 실제 클릭이 가능한지 확인합니다. 화면이 잘리면 해상도·배율·창 상태가 드러나는 전체 화면을 캡처합니다.

시작 창 크기를 작업 영역에 맞추는 코드는 이번 변경에 포함되어 있습니다. 공개 Release에 포함됐는지는 해당 Release의 커밋을 확인해야 하며, 실제 배율별 결과는 위 표에 따로 기록합니다.

## 키보드

마우스를 사용하지 않고 다음 순서로 확인합니다.

1. `Tab`과 `Shift+Tab`으로 검색, 상태 필터, 목록, 대여자, 메모, 동작 버튼을 이동합니다. 현재 포커스가 보여야 합니다.
2. 상태 필터와 장비 목록을 방향키로 조작합니다. 항목 선택 후 상세가 바뀌는지 확인합니다.
3. 메모를 입력한 뒤 `Esc`를 눌러 전송 전 입력이 취소되는지 확인합니다.
4. 다시 입력하고 대여 버튼으로 포커스를 옮긴 뒤 `Enter`를 누릅니다. 대여가 한 번 처리되고 이력이 한 건 생기는지 확인합니다.
5. 반납 버튼에서 `Enter`를 눌러 반납합니다. 처리 중이나 결과 미확인 상태에서는 `Esc`로 이미 보낸 요청이 사라지면 안 됩니다.

메모에 공백만 입력하거나 201자를 입력한 경우에는 검증 안내가 보이고 대여·반납이 실행되지 않아야 합니다.

## Narrator와 고대비

`Win+Ctrl+Enter`로 Narrator를 켭니다. 키보드로 검색·목록·대여자·메모·버튼을 이동하면서 이름과 역할을 구분할 수 있는지 확인합니다. 대여·반납 결과와 입력 오류가 낭독되는지, 같은 안내가 과도하게 반복되는지도 적습니다.

Windows 설정의 **접근성 → 대비 테마**에서 테마를 적용합니다. 글자, 포커스 표시, 선택 항목과 비활성 버튼을 구분할 수 있어야 합니다. 장비 상태는 색상과 함께 텍스트로도 확인합니다. 확인 후 테마와 Narrator를 원래 설정으로 되돌립니다.

## 연결 중단과 재연결

먼저 조회 캐시를 확인합니다.

1. 메모를 입력하지 않은 상태에서 API 창의 `Ctrl+C`로 API를 종료합니다.
2. 앱에서 새로고침합니다. 저장된 조회 범위 또는 이전 결과라는 안내가 있어야 하며 새 대여·반납은 실행할 수 없어야 합니다.
3. 첫 번째 창에서 같은 명령으로 API를 다시 실행하고 앱에서 새로고침합니다. 온라인 조회와 동작 가능 여부를 확인합니다.

입력 유지와 요청 재시도는 별도로 확인합니다.

1. API가 실행 중일 때 사용 가능한 장비를 선택하고 메모를 입력합니다.
2. API를 종료한 뒤 앱에서 대여합니다. 아직 연결 실패를 확인하기 전이므로 요청을 한 번 보관·전송하지만 완료로 표시하면 안 됩니다. 메모와 보관 요청이 남고 재시도가 가능해야 합니다.
3. 같은 데이터 폴더로 API를 다시 실행하고 재시도합니다. 대여 완료와 이력 한 건을 확인합니다.

입력 중에는 새로고침이 비활성화됩니다. 이는 입력 손실을 막기 위한 동작이므로 조회 캐시 확인과 입력 유지 확인을 나눕니다.

서버 저장 직후 응답만 유실되는 상황과 앱 재시작 복구는 [자동 시나리오](testing.md#자동-시나리오)로 따로 확인합니다. API를 종료하는 수동 확인과 응답 유실 시나리오는 다른 상황입니다.

## 결과 기록

결과는 실제 확인한 뒤에만 `통과`로 바꿉니다. `실패`에는 재현 순서와 화면을, 확인하지 못한 항목에는 이유를 적습니다. 기록과 캡처는 개인 폴더에 보관하고 Git에 넣지 않아도 됩니다.

```text
확인 날짜:

Windows 버전·빌드 / CPU 아키텍처:
해상도 / 배율 / 모니터 수:

첫 화면·창 크기: 미검증
100% 배율: 미검증
150% 배율: 미검증
Tab·Shift+Tab·방향키·Enter·Esc: 미검증
입력 검증: 미검증
Narrator 입력 이름·결과 안내: 미검증
고대비 글자·포커스·버튼: 미검증
API 중단·입력 유지·재연결: 미검증

```
